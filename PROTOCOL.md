# Duska line rebuild: protocol and current state

This file tells any analyst (human or AI) how this repository is worked, and where things stand. Read it before touching the data.

## What this is

An independent reconstruction of the paternal (father's father) line of Kevin J.S. Duska Jr., made from his own Duska archive, handed over one desktop folder at a time. It is run as a test: the finished AI tree will be compared with the tree Kevin built himself.

## Analyst brief (agent A-01)

Forensically reconstruct the genealogy of the owner of a computer in Calgary, working as a certified genealogist would, without holding the credential. Evidence is limited to the folders handed over, the analyst's training, and whatever is publicly reachable. Kevin may give other agents a different brief; the brief in force is recorded in `data/role.json`.

## Rules

1. One folder batch at a time. Kevin names each folder and says what it is. Log it in `data/folders.json`. A folder stays `open` until Kevin says it is complete.
2. Archive everything. Originals go to `records/<folder-id>_<name>/originals/` with a `MANIFEST.json` (sha256, bytes, pixels). Web-size copies go to `assets/pages/<folder-id>/`.
3. Every document gets an entry in `data/documents.json`: an entry-by-entry abstract in English, plus full transcription and translation of passages that bear on the line or are worth keeping. Mark doubtful readings with square brackets and a reading level (high, medium, low).
4. Every batch gets a blurb in `data/batches.json`.
5. Raise hypotheses, then solve them. Each hypothesis has a confidence, a basis and a named test. On each batch, rule on every open hypothesis the new evidence touches and log the change. Statuses: open, supported, solved, refuted.
6. Every fact on the tree (`data/people.json`) cites a source ID. Proof levels: stated, documented, inferred, prior.
7. Interesting or funny finds that are not about the line go to `data/curiosities.json`.
8. Requests for more material go to `data/requests.json` with status `held`. Raise them with Kevin only once a whole line has been processed from the folders given.
9. Blind test. Do not read Kevin's published tree or his one-name study site until the comparison phase, and do not read the accuracy page, the score feed or the Scorer's repo at all. Do not run open-web searches that combine the surnames with the villages (ruling X-011). Anything already known is logged in `data/priors.json`, and every search in `data/searches.json`.
10. Living people: exact birth dates stay out of this public repository. Years only.
11. Outside research is allowed and is logged in `data/leads.json` with a URL. A lead is not a finding.
12. After any data change run `python3 build.py` and commit `index.html` with the data.
13. This repo is one of three (Duska, Demko, Places) with a coordinator above them. This agent is the only writer here and merges its own work into `main` after every batch. Agents talk through `comms/` as set out in `comms/README.md`: read the other repos' outboxes at the start of each batch, write to your own.

14. Everything this agent receives comes from Kevin's Duska folder. A person in it who is not a Duska is still processed: index every named person in `data/candidates.json` with a `route` (the agent who should place them), send Demko and Hreskó people to the Demko agent, and send every household (village, house number, year, rite) to the Places agent.
15. The coordinator's ledger rules where lines touch. In force from ledger v2: labels and filing are priors and move nothing on their own (X-004); decide without waiting for Kevin and log it in `data/decisions.json` (X-005); a link is `solved` only on a record in hand with its archive reference, otherwise capped at 70 (X-009); a rule of law or custom recalled from training is marked as recalled (X-010); cite another agent by ID plus commit or date (X-008).
16. One batch, one commit on `main`, with the batch ID in the commit message. `.github/workflows/stamp.yml` hashes each commit and anchors it. Do not edit that file.
18. Cross-review (ruling X-012). At the start of every batch read the Demko repo's latest `main` (folders, documents, candidates, sources) and check it against the Duska line. Log the pass in `data/reviews.json` with the commit read and what was found, including nothing. A record there that belongs here: archive it under the same name with its checksum and transcribe it before reading theirs. A record here that belongs there: keep it and set `route` to `demko`.
19. Living status (ruling X-016): `living` is `true` only for Kevin; `false` where a death is stated or documented, or the person was born 100 or more years ago; `"unknown"` for anyone born less than 100 years ago with no death on record, shown by name and year only.
20. Reused names (ruling X-017, method note 1, section 3). A baptism is not an identity. Before attaching one to an adult, search burials for fifteen years after it and search forward for a later child of the same name; log the search. If the burial register is not in hand, set `necronym_risk: unresolved` and keep the link at 70 or below. Two baptisms with one name and one set of parents are two people. A change of mother between baptisms to one father is a second marriage until shown to be a second man. Use ages as written. Name reuse is ordinary working knowledge of the craft (ledger v10, X-017 item 6): it is not a statement by Kevin about this family and not a prior, and a reused name established from records is scored on its evidence like any other finding.
21. Images stay in the repo (ruling X-015 as reversed), except any image about Kevin himself or about a person of unknown status: log its name and checksum only. Every document carries a `provenance` block with "unknown" written out. Research passes use the open web only (X-011 item 6). Times are stored in UTC with a trailing Z (X-018).
17. `main` is public on duska.si within about an hour. Write blurbs and notes for a stranger. Tag each hypothesis with its `X-Q-NN` question where the ledger files it under one.
22. The unclassified folder (rulings X-019 and X-020, ledger v13). Kevin's folder `AAAA Unclassified` does not come to this agent directly. A separate Sorter divides it into piles in the private repository `primerogueinc/kevin-js-duska-jr-genealogy-private`. This agent reads `to-duska/` and `to-both/` there and nothing else; opening any other folder is reported to the coordinator for the contamination log. Each file taken is archived here as usual with the SHA-256 from the pile's `MANIFEST.json`, and the commit of the private repository that was read is logged in the batch. The pile a file is in is the sorter's label: proof level `prior`, no confidence moves on it (X-004). A file in `to-both/` is transcribed here before the Demko agent's reading is opened. A file that looks misfiled is reported to the coordinator and still processed if it bears on the line. Nothing about the lines Kevin has placed outside the experiment goes into this repository. The public checks (X-013, X-015 item 2, X-016) apply to everything taken.
23. Blind and open lines (ruling X-021, ledger v14). This line is blind and scored. Other agents in the same Project are not: the McGee agent works a question outside this line with everything Kevin knows, and the Sorter divides his mixed folder. This agent does not read their chats, any Project doc whose name begins `claude/mcgee-` or `claude/sorter-`, the folders `mcgee/`, `irish/`, `maternal/`, `about-kevin/` and `unknown/` of the private repository, or any memory note about the lines outside the experiment. It does not use the search of past chats inside this Project, which would reach those chats. Any exposure is reported to the coordinator for the contamination log. A fact about Ahn 4 or his children reaches this agent only through the coordinator, logged and scored as given.
24. Ahn 5 in Duska records (ruling X-022, ledger v15). When the marriage of Ahn 4 or the baptism of one of his children reaches this agent's pile: public are her name as the record gives it, the date and place of the marriage, and every field on Ahn 4's side; she is entered as Ahn 5 with `living: "unknown"`, name and year only. Withheld are her parents, birthplace, age or birth date, earlier residence and anything else that reaches into her own line; mark the place `[withheld: outside this experiment]`. The image is held (name and SHA-256 only) and goes, with the full transcription, to `irish/from-duska/` in the private repository. Nobody above Ahn 5 is added to the tree. Nothing learned from the withheld fields is used or relayed.
25. Held images. A document whose image cannot be published (about Kevin, about a person of unknown status, showing living third parties, or under rule 24) is entered in `data/documents.json` with `"held": "<reason>"`, its file name and SHA-256. The image is not copied into `records/` or `assets/`; the folder's `MANIFEST.json` lists it with `"image_in_repo": false`.
26. DNA (ruling X-023, ledger v18). This agent does not read, sort, transcribe or reason from DNA material. If a DNA file arrives, do not open it: tell Kevin and the coordinator. DNA is not used on this line until the paper tree is frozen and scored. Nothing from DNA goes into this repository.
27. Curiosities, every batch (ruling X-024). In every batch look for what a reader would repeat to someone else. Each entry in `data/curiosities.json` has the source ID, the original wording, a translation, one line on why it is worth keeping, and a tone: `funny`, `odd`, `sad` or `history`. Deaths and misfortunes are recorded straight. Every batch blurb ends "Curiosities: N", zero included. A curiosity moves no confidence.
28. Read the ledger every batch (ruling X-025). At the start of every batch read the coordinator's ledger as it stands (Project doc, or `ledger.md` in `primerogueinc/duska-coordinator`) and log the version read. The scoring rubric (`rubric.md` there) may be read; the score feed may not.
29. From ledger v19. The children of Ahn 4 other than Ahn 2 are not entered here unless a death is stated or documented; a record of one is held, with any given name in its file name withheld (X-016 item 6). A living third party's given name in a file name is written `NAME_WITHHELD` in the public copy (item 7). This agent never pushes to the private repository and transcribes no withheld field anywhere; Kevin gives such a file to the open agent himself (X-020 item 3, X-022 item 3). No user-built online family tree is opened (X-011 item 7). A link that rests on two capped links is shown at the cap with a `depends_on` list (X-009). The Project's document search is not used: it can return notes this agent may not read.
30. Every Duska is tracked (Kevin, 12 Nov, S-000-8). Any bearer of the surname met in the archive is indexed in `data/candidates.json` with `route: duska` and followed, wherever they lived. Tracked is not related: nobody is attached to a family group or the tree without a record, and a hypothesis of kinship is raised and scored like any other.
31. Kevin's own writings (rulings X-027 and X-028, ledger v20). Held unopened until the comparison phase: anything he compiled about the family (a family group record, an overview of baptisms, a list of people, a tree page, a file whose name states a conclusion). Readable: his guide to a kind of record or a collection, if it holds nothing about the family; stop and report if it does. Readable after this agent's own reading is written down: a transcription or translation made for him by someone else; any reading changed because of it is marked as given. No online-tree page is opened, whoever put it in a pile. A file name that states a finding is logged as a prior. The census of 1930 and 1940 is a public record and is read.
32. Shared files (the Demko agent's request, DM→DU-012). In a note about a file both line agents hold, give the file name and SHA-256 only. The reading goes in `data/`, so the other agent can read the image first. Before opening another agent's entry for a record, open the image and write the reading.
33. From ledgers v21 and v22. Kevin's word in this chat beats the ledger: act on it, log it as a statement, tell the coordinator in one line, and do not ask for confirmation (X-029). The coordinator keeps no copy of this board; a note to it carries only a new statement by Kevin, an exposure, or a question about publishing something on a person who may be living (X-030). Who is living is the table under X-016 in the ledger. Kevin hands over folders by kind: baptisms, census, deaths, marriages; do not ask him for a death or a marriage. Before relying on a document that is not a plain register strip, or whose kind is known only from a label, say what kind of object it is from its form, who made it and where it was kept, in the document's `object` field, with what it was compared against (X-031). If the ledger's version line has not changed, write nothing about it (X-025).

## Layout

    data/        people, candidates, families, decisions, searches, sources, hypotheses, batches, folders, documents,
                 curiosities, priors, leads, requests, role (all JSON)
    records/     original files as received, one directory per folder
    assets/      web-size page images used by the front end
    site/        template.html
    build.py     builds index.html (static, data inlined)
    index.html   the front end
